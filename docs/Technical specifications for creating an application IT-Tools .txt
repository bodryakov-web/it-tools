###Техническое задание на создание проекта IT-Tools.


##Задача.
Создай full-stack web-приложение представляющее собой интерфейс учебного курса для обучения студентов it-инструментам для бизнеса. 
Сам учебный курс в текстовом виде уже есть в файле формата .rtf.


##Применяемый стек технологий.
Web приложение должно быть создано без использования backend или frontend фреймворков или библиотек. 
Backend должен быть организован на чистом PHP без фреймворков и библиотек. 
Тексты уроков и другая информация должна хранится в базе данных MySQL в виде JSON.
Frontend должен быть только чистый HTML, CSS, JavaScript. 
Обязательно без фреймворков и библиотек, в т.ч. React и Next, чтобы можно было сделать деплой на простом хостинге.
Редактирование содержимого уроков должно осуществляться в редакторе CKEditor 5.


##Общее содержание и функционал web-приложения
Сайт должен выглядеть как последовательность уроков разбитых на разделы. 
Разделы могут меняться, добавляться и удаляться. 
Внутри разделов должны быть уроки. 
Уроки могут меняться, добавляться и удаляться.  
Для образца сделай 1 раздел и 1 урок в этом разделе. 
Будет примерно 5 разделов по, примерно, 5 уроков в каждом разделе.
Для каждого раздела и для каждого урока, для хранения в базе данных должен быть slug, который может содержать только маленькие английские буквы и дефис.
Структура URL должна быть примерно такая: 
section_number-<section_name>/lesson_number-<lesson_name>
Отдельной Главной страницы не нужно. 
В качестве главной страницы используется страница со списком уроков в виде кнопок-ссылок ведущих на страницы соответствующих уроков.

При заходе на сайт пользователь должен сразу попадать на страницу разделов. 
Разделы должны быть оформлены визуально как карточки. 
Каждая карточка раздела должна содержать заголовок раздела и кликабельные блоки-кнопки-ссылки заголовков уроков. 
Каждая такая кнопка-ссылка должна вести на страницу соответствующего урока.

Статистика по пользователям (кто какие уроки прошел) не нужна.
Регистрация пользователей не нужна.
Хранение пользователей в базе данных не нужно.

Каждый урок должен соответствовать отдельной странице.
HTML-страницы каждого урока должны формироваться динамически, при клике на заголовок или гиперссылку соответствующего урока соединяя единый шаблон урока и данные (учебный материал) полученный в формате JSON из базы данных.
Каждая страница должна быть в кодировке UTF-8 без BOM для корректного отображения текста на русском языке.
Нужно предусмотреть отдельную страницу 404/ошибки с кнопкой перехода на главную страницу.


##Описание урока
Каждый урок должен состоять из трёх секций:
1. теоретический материал, 
2. тестирование, 
3. лабораторная работа. 

Для секции теоретического материала заголовок "Теория" не нужен.

Тесты должны быть простого типа: вопрос, 4 варианта ответа из которых, только один правильный. 
Количество тестовых вопросов может быть разным для каждого урока (примерно 5-10). 
После каждого ответа - сразу, без нажатия кнопки проверить, пользователю показывается результат. 
Правильный ответ должен подсвечиваться зелёной галочкой, а неправильный - красным крестиком.
При этом данный блок вопроса блокируется, и пользователь уже не может выбрать другой вариант.
Прогресс и результаты прохождение тестов сохранять не нужно.

Секция лабораторной работы должна повторять, по функционалу, секцию теории.

В конце каждого урока должны быть кнопки предыдущий/следующий/в оглавление. 
Все данные урока, включая используемые в тексте изображения, хранятся в формате JSON в базе данных MySQL.
Все данные должны быть в кодировке UTF-8 без BOM для корректного отображения текста на 
Каждый урок должен быть доступен по своему уникальному URL, формируемому динамически через единый шаблон.

Добавление уроков должно быть похоже на добавление постов в блоге.

В Админ-панели должно быть предусмотрено добавление и удаление разделов, редактирование заголовков разделов,
добавление и удаление уроков, редактирование заголовков уроков, 
редактирование контента самих уроков. 
Удаление, добавление и редактирование должно обеспечиваться соответствующими кнопками с соответствующими текстами и всплывающими подсказками.
При удалении, модальное окно подтверждения не нужно.
В интерфейсе добавления/редактирования раздела и урока должно быть отдельное числовое поле для ввода порядкового номера раздела и урока.

В момент сохранения уроков должна быть валидация:
1. Поле названия урока заполнено и название не повторяется
2. Поле slug заполнено и slug не повторяется. Slug может содержать только маленькие английские буквами и дефисы, пробелы запрещены.
3. Порядковый номер заполнен и не повторяется.

Не нужно создавать функционал “сохранить черновик” и соответствующую кнопку. 
Должна быть только кнопка “опубликовать”, которая сохраняет контент урока в формате JSON в базе данных и публикует урок в открытый доступ.
После редактирования информации в админ-панели все изменения должны сохранятся в соответствующих записях базы данных в формате JSON. 
Все данные должны быть в кодировке UTF-8 без BOM для корректного отображения текста на русском языке.

Текстовый редактор CKEditor 5 должен быть на странице администрирования (админ-панели, админке) в секции теории и в секции лабораторной работы

##Описание программного интерфейса вставки тестовых вопросов и их преобразования в JSON.
Не нужно создавать интерфейс для добавления тестовых вопросов и вариантов ответов вручную. 
Должен быть программный интерфейс для автоматического преобразования последовательности блоков тестовых вопросов с 4 вариантами ответов, (из которых только один правильный (и отмечен галочкой в конце строки варианта ответа)).
На вход программного интерфейса, в специальное окно textarea, из документа формата .rtf, будет вставляться текст вида
"""
Что такое Linux?
Программа для создания сайтов
Операционная система ✓
Язык программирования
Текстовый редактор

Что такое ядро Linux?
Файловый менеджер в ОС Linux
Основная часть операционной системы ✓
Командная оболочка дистрибутива Linux
Редактор программ
"""
Т.е. блоки тестовых вопросов разделённых одной пустой строкой. 
В каждом блоке тестового вопроса первой строкой идёт сам вопрос заканчивающийся знаком вопроса '?'. 
Затем идут четыре варианта ответа, каждый на новой строке. 
Правильный вариант ответа отмечен галочкой (птичкой) в конце строки правильного варианта ответа.
Программный интерфейс должен преобразовывать переданный ему текст содержащий блоки тестовых вопросов в следующий формат JSON:
  "tests": [
    {
      "question": "Текст вопроса",
      "answers": ["Ответ 1", "Ответ 2", "Ответ 3", "Ответ 4"],
      "correct": 2
    }
  ],
Т.е. вопрос попадает в поле "question", четыре варианта ответов попадают в поле "answers", номер правильного ответа (тот, который отмечен галочкой) вставляется цифрой в поле "correct".
После формирования соответствующего JSON, вся структура вставляется в поле "tests" контента урока.

Если урок редактируется, происходит обратное преобразование из JSON в текст.

При таком подходе .htaccess не выполняет сам роутинг. 
Его единственная задача — перенаправлять абсолютно все запросы пользователей на один-единственный PHP-файл index.php, если запрос не касается существующих файлов (картинок, CSS, JS).

Вход в админку по адресу: /bod .
404 страница: любой некорректный URL.

Должен быть реализован полноценный CRUD функционал запросов с PHP на MySQL на создание, изменение, удаление разделов и уроков.

Максимальная ширина контента на экранах больше 1920px должна быть ограничена 1900 px.
На меньших ширинах экранов - ширина контента должна быть адаптивной (через функцию clamp).

Вверху всех страниц сайта должна быть узкая (минимальной высоты) полоса header-а.
В этой полосе header-а, слева должен быть заголовок сайта: 'IT-Tools'.
На ширинах >= 1000px должна также появляться в центре надпись: "IT инструменты для бизнеса".
На ширинах >= 1920px надпись в центре должна меняться на: "IT инструменты для бизнеса (анализ данных, визуализация, боты, программирование без кода, автоматизация, ИИ)".

Снизу должна быть полоса footer-а, с текстом по центру: 
"IT-Tools" .
А на экранах с шириной >= 1000px с текстом:
"2026 | IT-Tools  | Автор: преподаватель ГТК - Бодряков А.Ю." .
А на экранах с шириной >= 1500px с текстом:
"2026 | IT-Tools - Учебный курс по IT-инструментам для бизнеса | Автор: преподаватель ГТК - Бодряков А.Ю." .
Должно быть переключением светлой и тёмной темы с кнопкой в header-е справа. 
Эти две полосы header и footer не должны быть фиксированы, т.е. должны прокручиваться вместе с контентом.

Цветовая схема должны быть в серых оттенках, с разной степенью светлоты серого, построенные через CSS-переменные и модель OKLCH . 
Базовая тема светлая.

Промотка должна быть плавная. 


##Правила для JavaScript кода
В коде JavaScript, для поиска элементов через querySelectorAll() должны использоваться data-атрибуты, а не классы или ID. Классы должны использоваться только для CSS-стилизации. Соответствующие data-атрибуты должны быть в HTML-коде.
